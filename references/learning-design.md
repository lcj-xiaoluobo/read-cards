# 卡片与问答设计

## 先选学习目标

- 概念：能说清定义与关键区分。
- 机制：能解释条件如何作用于结果。
- 方法：遇到场景能选择操作并知道何时不用。
- 发现：能在研究对象与时间范围内表述证据。
- 对比/边界：能依据具体条件区分两个选项。

一张卡允许包含理解目标必需的多个条件；不要把一个效应估计拆成丢失人群、比较与时间窗的数值记忆卡。相互独立的目标再拆卡。

## 问题与参考答案

提问与复述用贴近原书的自然语言，不套用标题的诗意或仿古文风。题面写明对象和条件，避免提示答案或要求泛泛“谈谈感受”。答案先直接响应，再给必要解释；answer_points 为 1–3 个客观检查点，检查点是同一个学习目标的判定要点，不是三道新问题。数字卡保留单位与分母；机制卡问因果链与条件；行动卡问如何选择而非背章节编号。

差："根据第 3 章，什么最重要？" —— 离开书就无法理解。

好："只有某章正文时，能否声称完成了整书卡片拆解？为什么？"

答案："不能，只能声明覆盖该章节；目录不等于读取全文。"

检查点：指出章节范围；区别目录与实际阅读。

差："同时解释概览、提取、筛选、验证和 SQ3R 全部步骤。" —— 混合多个目标。

好："候选里没有原文反例时，应如何处理反例模块？" —— 可独立核对一个操作原则。

## 内容驱动而非凑字段

边界写具体误用情形。原文章要求至少两条，本技能以实际内容为准；不要为了凑两条发明限制。来源没讨论局限时可注明“来源未说明进一步局限；范围只限本材料”，把自己推导的误用提醒标为模型补充。

方法卡重构优先包含“在什么条件下 → 做什么 → 为什么 → 何时停下或改用其他方法”。出处是依据，不能代替解释。作者提出但未检验的建议仍称作者主张。

## 自测与复习记录

先根据 Question 自行回答，再在 HTML 单卡之外展开参考答案，对照 answer_points 核对理解。卡面不展示参考答案或边界，页面不提供自评按钮与掌握筛选；旧数据中的学习状态只保留，不显示。复习区记录用户自己的回忆与应用反馈，不承诺个性化间隔效果。

Review 只存用户自己的回忆、应用反馈或疑问，默认空白。新数据增加 answer 和 answer_points；旧数据没有 answer 时兼容用 reconstruction 显示参考，但不要声称旧题已经过重新设计。

已有卡片修订：保留稳定 ID 和用户记录，核对旧题与新题是否仍是同一个目标。目标改变则用新 ID，说明记录不应自动继承。冲突观点可分别成卡并关联，不让强行合并抹掉分歧。
